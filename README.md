# Бот-напоминалка для SMM-агентства

Telegram-бот, который убирает из работы контент-агентства ручной пересчёт дедлайнов.
Читает контент-планы (Google Sheets) и календарь доступности операторов (Google
Calendar), сам считает, что и когда нужно сделать по бизнес-правилам агентства, и
предлагает даты съёмок исходя из реальной загрузки. Ничего не редактирует в
источниках — только читает.

## Проблема

В агентстве десяток проектов, у каждого свой контент-план в Google Таблицах.
Дедлайны на сценарий, съёмку, монтаж и картинку каждый раз пересчитывались вручную
от даты выкладки — а сами таблицы никогда не были однородными: разные названия
колонок, разный регистр («Рилс»/«рилс»/«Reels»), где-то тип контента в отдельной
колонке, где-то его нет вовсе. Бот берёт этот пересчёт на себя и каждый вечер
присылает команде, что нужно поставить в работу завтра.

## Что делает

- **Ежедневная сводка** (будни вечером) — что поставить в работу завтра, посчитано
  обратным ходом от дат выкладки: сценарий, раскадровка, монтаж, картинка, отправка
  клиенту на согласование — каждое со своим сроком в рабочих днях.
- **Съёмки — не просто дедлайн, а предложение слота.** Бот видит, кто из операторов
  свободен в календаре, батчит рилсы одного проекта по 5 штук на сессию (снимаются
  одной поездкой) и сразу пишет: «Назначить съёмку, доступные слоты: ... — рилсов
  N: темы». При конкуренции нескольких проектов за одну неделю — распределяет по
  дням, а не пытается впихнуть всё в один.
- **Недельный отчёт** по пятницам — что сделано и что в работе по каждому этапу
  воронки: сценарии, съёмки, монтаж, публикации.
- **`/today`, `/tomorrow`, `/date`** — та же логика по запросу, на любой день.
- Предупреждает отдельным блоком о контенте без даты выкладки или строках, которые
  не удалось разобрать — так, чтобы команда сама доразметила, а не бот гадал.

## Технически интересное

- **Разбор негладких таблиц.** Колонки ищутся по ключевым словам в заголовке
  («дата», «формат»/«вид»/«тип», «тема»), а не по фиксированной позиции — потому что
  у разных проектов они в разных местах, а иногда в одном листе есть сразу и «Вид»
  (реальный тип), и «Формат» (жанр вроде «Анонс»/«Байка»), и на приоритет ключевых
  слов завязано, какая колонка какая.
- **LLM только как fallback.** Если словарь синонимов не смог определить тип
  контента по ключевым словам — строка уходит на классификацию в LLM, результат
  кэшируется навсегда. Если LLM недоступна — на бота в целом это не влияет,
  страдает одна нераспознанная строка, а не весь скан.
- **Рабочие дни без внешних справочников.** Агентство работает по праздникам —
  единственные нерабочие дни это суббота и воскресенье, поэтому производственный
  календарь РФ не нужен вообще, вся арифметика дат — чистые функции без сети.
- **Подбор слотов — обычный constraint-поиск**, не ИИ: окно ±1 рабочий день вокруг
  расчётной даты съёмки, только дни, где у операторов есть слот в календаре,
  нагрузка распределяется по дням при конкуренции проектов.
- **Устойчивость к сбоям API.** Контент-планы пересканируются раз в сутки и
  кэшируются в SQLite — вечерний джоб не дёргает Google на каждое сообщение и не
  падает молча при недоступности Drive, а откатывается на предыдущий кэш.
- **Формат сообщений под Telegram**, а не просто текст: задачи группируются по
  проекту в сворачиваемые цитаты (`<blockquote expandable>`), длинные сообщения
  режутся по границам HTML-блоков, а не по числу символов — иначе разрез мог попасть
  внутрь тега и Telegram отклонял бы сообщение целиком.

## Стек

Python 3.11+, aiogram 3, APScheduler, Google Sheets/Drive/Calendar API (service
account, доступ только на чтение), SQLite, опционально Anthropic API как fallback-парсер.

## Запуск

```bash
pip install -r requirements.txt
cp .env.example .env          # заполнить
# credentials.json — service account; расшарить на него папки Drive и календарь (чтение)
python test_rules.py          # проверка расчётов и парсера
python bot.py
```

Джобы: вечер пн–пт (час задаётся `/time` или `DAILY_HOUR` в `.env`, МСК) — план на
следующий рабочий день; пятница 12:00 МСК — недельный отчёт. Контент-планы
пересканируются раз в сутки, кэш в SQLite (`DB_PATH`), при недоступности Drive
работает старый кэш.

Команды:
- `/today`, `/tomorrow` — сводка на сегодня/завтра
- `/date 14.08.2026` — сводка на конкретную дату
- `/time 20` — час (МСК) ежедневной рассылки; сохраняется в БД, переживает рестарт
- `/plan` — тот же текст, что уйдёт в вечернем джобе
- `/report`, `/shoots`, `/rescan`

## Прод (VDS)

Всё через env и относительные пути, без Windows-специфики. systemd:

```ini
[Service]
WorkingDirectory=/opt/bulon-bot
EnvironmentFile=/opt/bulon-bot/.env
ExecStart=/opt/bulon-bot/.venv/bin/python bot.py
Restart=always
```

## Файлы

- `rules.py` — рабочие дни, дедлайны, подбор дат съёмок (вся бизнес-логика, чистые функции)
- `plans.py` — Drive/Sheets/Calendar, разбор листов, LLM-fallback, суточный кэш
- `bot.py` — aiogram, APScheduler, тексты сообщений
- `db.py` — SQLite: кэш планов, кэш LLM, лог отправленных (защита от дублей при рестарте)

## Тесты

```bash
python test_rules.py
```

Проверяют расчёт дедлайнов, разбор контент-планов (в т.ч. на реальных структурах
таблиц с разными шапками), подбор слотов съёмок и упаковку Telegram-сообщений.
